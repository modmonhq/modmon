---
title: Known limitations
description: Current user-visible limitations and unsupported combinations.
---

Check these limits before choosing a setup. See
[supported features](./capability-matrix.md) for the full runtime comparison.

| Area                    | Limitation                                                                                                                                                                                                                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cluster targets         | A service runs one container on each node its `placement` names unless it sets `replicas` or `autoscale`, and nothing is rescheduled when a node goes down. A named volume stays on its node; a shared volume is a network mount, too slow for databases. Services on different nodes share the networks of `mm.yaml` and reach each other by service name. A node's `mmd` answers the names of that node's containers: while it is stopped, they resolve nothing. Compose `dns` keys, `links` aliases, and IPv6 addresses are not supported on these networks; see [the limits](../remote-daemon.md#service-names-across-nodes). Moving a service does not move its volumes. Exec and forwards for a service on several nodes reach the first of them. Logs are merged in the order of the nodes' clocks, so nodes whose clocks differ can swap lines that are close together. See [place services on nodes](../remote-daemon.md#place-services-on-nodes). |
| Bind mounts             | Local development bind mounts are supported on local targets with Podman Compose or Docker Compose, not on remote targets.                                                                                                                                                                                                                               |
| Remote commands         | Status, logs, and reviewed deployments use the SSH daemon. Remote exec has no stdin, TTY, or interactive shell support.                                                                                                                                                                                                                                  |
| AI agents               | A remote host enforces an agent's limits. On your own machine they are a guardrail: an agent with an unrestricted shell can run the container engine itself. `mm_exec` output is not redacted. See [agents](../mcp.md#what-this-does-and-does-not-protect).                                                                                              |
| Compose secrets         | Docker Compose has no native persistent secret store. Delivery uses a private operation file; non-default UID/GID/mode and unreconstructable rollback are rejected.                                                                                                                                                                                      |
| Job secrets             | Compose jobs reuse their service's environment and secret mounts. Build secrets use a separate BuildKit path.                                                                                                                                                                                                                                            |
| Local services          | Ingress, dashboard, Mailpit, and access-gate components require HAProxy with Linux systemd, or macOS with Docker Desktop and Docker Compose. Other macOS engines such as Colima, and remote/clustered service orchestration, are not supported. On macOS, launchd agents start at login, so local HTTPS is unavailable while you are logged out. |
| Managed secret backends | OpenBao and Vault can run locally with Docker Compose or rootless Podman Compose. Managed remote lifecycle operations are unsupported. These are development setups, not production high-availability services.                                                                                                                                          |
| Local TLS               | Fedora/RHEL trust support has no dedicated live runner. Unknown trust-store layouts fail closed.                                                                                                                                                                                                                                                         |
| Non-Unix private files  | Unix-equivalent owner-only permission enforcement is unavailable, so features requiring that guarantee fail closed.                                                                                                                                                                                                                                      |

mm reports unsupported combinations before applying a change.
